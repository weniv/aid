## 0. 구현 방식 확정 & 골격 작업 결과 (2026-06-01 갱신)

운영 측 결정으로 **자체 폼이 아니라 구글폼(버튼 → 새 탭 이동)** 방식으로 확정. §6·§7의 자체 폼 설계는 폐기하고 아래 골격으로 대체한다.

### 신청 플로우 (2026-06-01 단순화)
1. **헤더 "신청하기"** / **APPLY "신청하기"** → 둘 다 `#schedule` 로 내부 스크롤(부드러운 앵커 이동).
2. 사용자는 SCHEDULE 표에서 **원하는 회차**를 선택.
3. 해당 회차의 **"접수하기"** 버튼이 새 탭으로 구글폼을 연다.

### 골격 상태
- **APPLY 섹션**(`index.html`): "신청하기"(→`#schedule`) + Discord 문의 + 개인정보 안내 1줄. 형태 자체는 폼 진입이 아니라 "회차 선택으로 안내"하는 클로징.
- **SCHEDULE 접수 버튼 8개**: `.schedule-apply[data-form-link]` + `aria-disabled` → "준비중" 뱃지로 표시.
- **단일 지점 제어**: `assets/apply-link.js` 의 `SCHEDULE_FORM_URL` 한 곳만 채우면 8개 버튼이 새 탭 구글폼으로 활성화. 미입력 시 자동으로 비활성 + "준비중" 뱃지 유지.
- **개인정보**: 별도 처리방침 URL 없이 신청서(구글폼)에서 개별 동의서 수령. 랜딩엔 "신청서 작성 시 동의 수령 · 5년 보관 후 파기" 안내(`.apply-consent`).
- 변경 파일: `index.html`, `assets/apply-link.js`, `assets/landing.css`.
- **남은 일**: 구글폼 URL 수령 → `SCHEDULE_FORM_URL` 입력 → 끝. ([추후적용-항목 #1](추후적용-항목.md))

## 1. 배경 · 문제 정의

이 랜딩페이지의 **유일한 전환 목표는 "과정 신청"** 인데, 현재 작동하는 신청 진입점이 **0개**다.

| 근거(파일:줄) | 문제 |
|---|---|
| `index.html:444` | `<a href="mailto:">` — 빈 mailto. 클릭 시 빈 메일 클라이언트만 열림 (깨진 링크) |
| `index.html:365~424` | "접수하기" 버튼 8개 전부 `aria-disabled="true"` + `href="#"` (신청 불가) |
| `index.html:438` | APPLY 섹션이 "위 일정에서 회차를 선택해 신청하라"고 안내하지만, 정작 그 일정 버튼이 모두 비활성 → **막다른 순환(dead-end loop)** |
| 전역 | `<form>`/`<input>` 0개 — 페이지에 폼 자체가 없음 |

→ 트래픽·카피·디자인을 개선해도 전환은 구조적으로 0. **P0(최우선)**.

## 2. 제약 조건

- 바닐라 HTML/CSS/JS + Three.js, **빌드 도구·프레임워크 없음**, 정적 호스팅(GitHub Pages 추정) → **서버 측 폼 처리 불가**.
- 디자인 토큰 `style/tokens.css`(`--primary` 등), 버튼 `style/components.css`(`.btn` 계열) **재사용 전제** (새 색 하드코딩 금지).
- 사용자 선호: **절제·최소 마찰** (과밀 UI·과한 톤 지양).

## 3. 필드 세트 (마찰 최소화)

선발 기본요건 3가지(만 30세 이상 / 재직자·최근 3년 직무경험 / 제주 거주·근무)는 자격 스크리닝에 필요하나, **서술형 강요는 이탈을 유발**하므로 1차 신청은 최소화한다.

### 1차 신청 — 필수 (입력 부담 최소)
| 필드 | 타입 | 비고 |
|---|---|---|
| 이름 | text | |
| 휴대폰 | tel | 합격 통보 채널 |
| 이메일 | email | 통보·자료 발송 |
| 희망 트랙 | select (G/T/N/S) | 어떤 과정인지 |
| 자격 확인 3종 | checkbox ×3 | "만 30세 이상" / "재직 중 또는 최근 3년 직무경험" / "제주 거주 또는 제주 근무" — 서술 없이 체크로 스크리닝 |

### 후속/선택 (1차에서 제외 → 면접·선발 단계로 이연)
- 학력, 경력기간, 상세 직무경험, 기대효과(서술형) → **1차에서 받지 않음.** 선발 면접 또는 합격 후 수집.
- 근거: 서술형 필드는 모바일 재직자에게 가장 큰 마찰. 1차는 "연락 가능 + 자격 충족 + 트랙"만 확인하면 충분.

### 멀티스텝 여부
- **단일 스텝 권장.** 필드가 7~8개로 적어 단계 분할은 오히려 과함.
- 단 시각적으로 길어 보이지 않게 **그룹핑**: ① 기본정보 ② 자격확인 ③ 동의.

## 4. 개인정보 수집·이용 동의 (필수 · 개인정보보호법)

> 누락 시 법 위반. "있으면 좋은 것"이 아니라 **필수**.

- **수집 항목**: 이름, 휴대폰번호, 이메일, 희망 트랙, 자격요건 해당 여부
- **이용 목적**: 교육과정 신청 접수 · 선발 · 합격 통보 · 교육 운영 안내
- **보유 기간**: 사업 종료 후 1년(예시) 또는 관계 법령상 기간, **동의 철회 시 즉시 파기** (실제 기간은 운영 측 확정 필요)
- **동의 분리**:
  - (필수) 개인정보 수집·이용 동의 — 미동의 시 신청 불가
  - (선택) 향후 과정·이벤트 안내 수신 동의 — 미동의해도 신청 가능
- **처리방침 링크** 제공 (별도 페이지 또는 모달)
- **다크패턴 금지**: 선택 동의 기본 체크 ❌, 필수/선택 시각적 명확 구분, 강제 끼워넣기 ❌

## 5. 전환 퍼널 · 배치

```
히어로 주 CTA "모집 신청하기"
        │ (스크롤/앵커)
        ▼
   [ 신청 폼 섹션 ]  ← APPLY 섹션을 '링크 모음'에서 '실제 폼'으로 교체
        │
   Discord·문의는 보조로 강등 (주 CTA와 위계 분리)

모바일: 스크롤 중 항상 노출되는 sticky "신청" 바 (uiux-designer 협업)
```

- **APPLY 섹션 교체**: 현재의 막다른 링크 3종 → 실제 신청 폼. Discord/문의는 폼 하단 보조 링크로.
- **SCHEDULE 비활성 버튼 처리**: 일정 미확정 상태에선 "접수하기"(비활성) 대신 → **"신청 폼으로 이동" 또는 "오픈 알림 신청"** 으로 전환. 일정 확정 후 회차별 폼/링크로 연결.
- **사실 기반 긴급성만**: "회당 30명 내외(최대 40명 미만) · 선착순" (사업계획서 사실). ❌ 가짜 카운트다운·허위 잔여석.

## 6. 구현 옵션 비교 (빌드 도구 없음 전제)

| 옵션 | 장점 | 단점 | 개인정보 |
|---|---|---|---|
| **(a) Google Forms 링크/임베드** | 개발 0, 시트 자동수집, 비개발자 운영, 무료 | 브랜드 이질감(iframe), 외부 이탈(링크), LCP 부담 | 구글(해외) 저장 → 위탁·국외이전 고지 필요 |
| **(b) 자체 폼 + 서드파티 엔드포인트** (Formspree/Web3Forms 등) | 페이지 내 네이티브 폼(브랜드 일관), 백엔드 불필요, 메일 알림 | 서드파티 의존, 무료 한도, 스팸 대응 | 동의 UI 직접 구현(정밀) + 위탁 고지 |
| **(c) 자체 폼 + Google Apps Script 웹앱** | 네이티브 폼 + 운영자 구글시트 직수신(추가 서드파티 X), 무료 | Apps Script 배포·CORS 약간의 기술 | 동의 직접 구현 + 데이터는 운영자 구글 계정 |

### 권장: **(b) 또는 (c) — 자체 폼 + 외부 제출**
- 이유: 정부지원 교육은 **신뢰가 전환을 좌우** → 브랜드 일관성·페이지 내 완결성 중요. 개인정보 동의도 정밀 구현 가능.
- **(a) 구글폼 링크**는 "빠른 임시 오픈"용 폴백으로만.
