## 1. 배경 · 문제

히어로 Three.js 신경망 애니메이션(`assets/hero-scene.js`)에 두 가지 리스크가 있었음:

1. **`prefers-reduced-motion` 미존중** — 끊임없이 회전·궤도·스크롤 임팩트 애니메이션이 돌아 멀미·전정기관 민감 사용자에게 접근성 위반. 30+ 타깃에선 특히 민감.
2. **WebGL 미지원/실패 fallback 없음** — 구형·저사양·정책 차단 환경에서 WebGL 생성이 실패하면 히어로가 깨지거나 빈 화면. 첫인상 손실.

(이미 적용돼 있던 것: pixelRatio 캡 ≤2, IntersectionObserver로 화면 밖 렌더 정지)

## 2. 적용 내용 (`assets/hero-scene.js`)

| 항목 | 처리 |
|---|---|
| WebGL 폴백 | `WebGLRenderer` 생성을 `try/catch`로 감싸 실패 시 `canvas.style.display='none'` 후 `return`. → `.hero`의 **CSS 그라디언트 배경이 그대로 노출**(이미 존재)되어 자연스러운 폴백. |
| 컨텍스트 유실 | `webglcontextlost` 리스너 추가 → `preventDefault()` + 애니메이션 루프(`raf`) 중단. (드라이버 리셋·탭 전환 대비) |
| reduced-motion | `matchMedia('(prefers-reduced-motion: reduce)')` 감지 → 참이면 **애니메이션 루프 없이 정적 1프레임만 렌더**하고 종료. 회전·궤도·스크롤 임팩트·마우스 패럴랙스 모두 정지. |

- **검증**: `node --check` 문법 OK · reduced/ webglcontextlost/ catch 분기 확인 · dev 서버 HTTP 200.

## 3. 설계 판단

- reduced-motion 시 **완전 제거가 아니라 정적 1프레임**: 시각적 키비주얼(신경망)은 유지하되 모션만 제거 → 디자인 손실 최소화 + 접근성 충족.
- WebGL 실패 시 별도 폴백 이미지 없이 **기존 CSS 그라디언트 배경 재사용** → 추가 에셋·코드 부담 없음(절제).

## 4. 남은 일 / 후속 (별도 작업 단위)

이번 건은 "히어로 모션·WebGL"에 한정. 나머지 a11y/perf 항목은 후속:
- **WCAG 대비**: `--grayLv3`(#8d9299)·반투명 배경 위 텍스트 4.5:1 점검
- **키보드/포커스**: focus-visible 표시, 스킵 링크, 탭 순서
- **폰트/LCP**: `pretendard.woff2` 2MB preload·subset, 강사 이미지·OG 이미지(1.7MB) 최적화
- 배포 후 Lighthouse(LCP/CLS/INP) 측정
